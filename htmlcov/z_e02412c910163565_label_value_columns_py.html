1"""Labels as columns: `key=value` split into a value, a bare tag into a flag. 

2 

3Cohorts encode their conditions in labels: a sweep over a time budget tags its 

4runs `budget=250`, `budget=450`, and so on. In a CSV those want to be a `budget` 

5column holding `250`, not a substring of a joined label cell that has to be 

6parsed again in R. 

7 

8The conditions that are not `key=value` want a column just as much. A run is 

9tagged `baseline_oss` or `random_seed` or it is not, and that is the grouping 

10variable for a whole cohort. Without a column, filtering on one means 

11substring-matching the joined `labels` cell, which is the thing this repository 

12learned not to do the hard way: `"baseline" in labels_text` also matches 

13`baseline_oss`, and matching on the joined cell once destroyed the eval-derived 

14labels of 40 runs. 

15 

16So a bare tag becomes `label_flag.<tag>` holding `True`. The prefix is separate 

17from `label.` because a cohort can carry both `budget` and `budget=800`, and 

18merging them would put a flag and a value in one column. 

19 

20A run that does not carry the tag has an empty cell rather than `False`. The 

21column set is the union across the selection, and a run's own labels are read 

22without knowing which tags the other runs carry. Empty therefore means the run is 

23not tagged, which for labels is knowable and total: `labels.json` lists every tag 

24a run has. The legend's coverage count reads as how many runs carry the tag. 

25 

26A duplicate key keeps the first label in sorted order, so the cell is the same 

27whatever order the labels were written in. That case means the run was tagged 

28inconsistently, and picking deterministically beats picking arbitrarily. 

29""" 

30
