1"""Checks on a scenario's package that only mean something before it is installed. 

2 

3:mod:`glossogen.scenario_conformance` checks a built scenario, which says nothing 

4about the distribution around it. These are the other half, and every one of them 

5is a failure that installation either hides or converts into something harder to 

6read: 

7 

8``package-data`` that omits the prompts installs a wheel that renders nothing, 

9while the editable install the author is testing against works fine. An 

10entry-point group naming another contract version is not read at all, so the 

11scenario is simply missing from the list. A non-empty ``__init__`` breaks event 

12discovery, which runs while the event union is mid-import. A name a built-in 

13already holds stays with the built-in, and the collision is only logged, so 

14validating by name afterwards reports a healthy scenario: somebody else's. 

15 

16A check that cannot be evaluated returns a note rather than a verdict, because a 

17false failure teaches a reader to skip the output. 

18"""
