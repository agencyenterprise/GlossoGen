1"""Pass 3 of the communication-feature analysis pipeline. 

2 

3Reads a consolidated ontology JSON file (produced by 

4``scripts/consolidate_communication_ontology.py``) and asks the LLM 

5judge to score each ontology category on this run's primary-channel 

6messages. The result is a per-run feature-presence vector written to 

7``communication_feature_presence.json`` alongside the run's other 

8sidecars, and one ``Measurement`` whose ``score`` is the number of 

9categories above the 0.5 confidence threshold. 

10 

11The ontology path defaults to the most recently modified JSON under 

12``<runs_dir>/<scenario>/_ontology/`` (derived from ``run_dir``); 

13``--ontology-path`` only needs to be passed to pin to a specific 

14version. 

15 

16Scenario-agnostic: the metric calls 

17``scenario.build_communication_rounds(events)`` and only sees 

18``CommunicationRoundView`` rows. Scenarios that do not implement the 

19hook return ``[]`` and the metric quietly skips with no Measurement. 

20"""
