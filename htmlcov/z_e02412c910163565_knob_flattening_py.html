1"""Turning a run's recorded scenario config into flat, named columns. 

2 

3The recorded config is the source of truth here, not any knobs model. A scenario's 

4knobs class ignores extra keys, so it cannot tell you what an older run actually 

5ran with; the `scenario_config` on the run's first event can. 

6 

7One flattening rule, applied everywhere, with no per-knob special cases: 

8 

9* a scalar is its own column 

10* a mapping is exploded recursively with dotted keys, so `model_overrides` 

11 becomes `model_overrides.field_observer.model` 

12* a list becomes one column holding compact JSON 

13 

14Lists stay whole because the ones that appear here have no sane column expansion. 

15`scheduled_events` is a list of tagged objects whose length varies per run, so 

16exploding it by index would invent columns that mean different things in different 

17rows. 

18 

19The column set therefore depends on values and not only on top-level keys: two 

20runs of one scenario whose `model_overrides` name different agents contribute 

21different columns. That is the same sparseness a mixed-scenario selection 

22produces, and it needs no separate handling. 

23"""
