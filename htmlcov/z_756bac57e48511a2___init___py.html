1"""Test a scenario or metric that ships in its own package. 

2 

3A scenario is only exercised by running one, and running one means an MCP 

4server, agent sessions, a game clock and an event log. This package supplies all 

5of that with the LLM replaced by a script, so a test states what each agent does 

6and asserts on what the platform did with it. 

7 

8Time is the reason this exists rather than being written per package. A run 

9waits out `MIN_ROUND_DURATION_SECONDS` after the last message to guess whether 

10the agents have finished, and counts idle sessions on an interval. A test with 

11scripted agents knows when they have finished, because it wrote the scripts, so 

12the harness answers that question directly instead of waiting. It also replaces 

13the provider-backed token counter, which otherwise posts every message to a 

14provider for a number no test reads. See "Tests and time" in CLAUDE.md. 

15 

16Install the extra to get pytest, which `run_simulation` takes a `MonkeyPatch` 

17from: 

18 

19 pip install "glossogen[testing] @ git+https://github.com/agencyenterprise/GlossoGen.git@<tag>" 

20 

21What a scenario author needs, in order: 

22 

23- `glossogen validate <name-or-directory>` covers the static contract: channels that 

24 exist, roles that match the agents, presets that still validate, templates that 

25 render. It is a command rather than part of this package, so it needs no test 

26 suite to run. `assert_scenario_is_registered` covers the one thing it cannot, 

27 that the name resolves to your class and not to somebody else's. 

28- `run_scenario` / `run_rounds` drive the real round loop with scripted agents, 

29 and the `assert_*` helpers state what a finished run must contain. 

30 

31`metric_harness` is the equivalent for a metric: it scores a finished run 

32through `run_scenario_evaluation`, the same function `glossogen evaluate` calls, 

33with a stub judge whose answers the test chose. 

34"""
