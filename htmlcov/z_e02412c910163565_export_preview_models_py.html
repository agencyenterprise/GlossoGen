1"""What a selection would produce, described before anything is built. 

2 

3The preview is computed from the same records the export itself reads, so the 

4columns it offers are exactly the columns the export can fill. There is no static 

5column list anywhere that could drift from the data. 

6 

7Per-column coverage counts are what make a mixed-scenario export readable. A knob 

8only one of two scenarios defines is blank on the other's rows. A caller that knows 

9the column is filled in 8 of 128 runs can say so, and the reader stops wondering 

10whether the blanks are a bug. 

11 

12All three ceilings are reported here, so a caller renders the limit the endpoint 

13actually enforces instead of its own copy. Only the raw one comes with an estimate to 

14compare against: CSV bytes are counted during the write and never predicted, 

15so a caller can state that ceiling but not tell in advance whether a request will 

16reach it. 

17""" 

18

22class ExportValueColumn(BaseModel):

24

26 ``runs_with_value`` is how many runs in the selection have a non-empty cell. 

27 ``always_included`` marks the identity columns, which every frame emits. 

28 """

37class ExportMetricColumn(BaseModel): 

38 """One evaluator metric an export can carry. 

39 

40 ``rounds_reported`` is how many round observations this metric carries across 

41 the selection. It is not a row count: every metric is a column, so metrics 

42 share the rows they fall on. The largest of them is what a caller estimates 

43 the round table's height from, since one metric's rounds are usually a subset 

44 of another's rather than disjoint. 

45 

46 There is no per-metric agent count. The agent table is keyed on the run's 

47 registered roster, so its height is ``agent_row_count`` on the selection and 

48 no choice of metrics moves it. 

49 """ 

50 

51 metric_name: str 

52 label: str 

53 score_unit: str 

54 runs_with_value: int 

55 rounds_reported: int

58class MultiRunExportPreview(BaseModel): 

59 """Everything a client needs to describe an export before requesting it. 

60 

61 ``raw_bytes_estimate`` is the on-disk size of the run folders a raw export 

62 would carry, and is ``None`` when it was not asked for. ``missing_run_ids`` 

63 lists explicitly named ids that no longer resolve to a run this group owns. 

64 

65 ``agent_row_count`` and ``message_row_count`` are what the agent and message 

66 tables would hold. Both are run-level totals rather than per-metric ones: an 

67 agent row is an agent and a message row is a message, so no choice of metrics 

68 changes either. The agent count is the registered roster, which is what that 

69 table is keyed on. 

70 

71 ``round_context_row_estimate`` is the rounds the selection played, which is 

72 what a table of one row per run and round holds. It is an estimate and named 

73 one, because a round nothing was injected in has no row and the preview does 

74 not open the event logs to find out. 

75 """ 

76 

77 run_count: int 

78 run_ids: list[str] 

79 scenario_names: list[str] 

80 evaluated_run_count: int 

81 in_progress_run_count: int 

82 runs_without_report: list[str] 

83 missing_run_ids: list[str] 

84 raw_bytes_estimate: int | None 

85 agent_row_count: int 

86 message_row_count: int
